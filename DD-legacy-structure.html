🗺️ 기존 ERP 구조 분석

레거시 ERP(JAEHO) 실제 구조 확인 결과 — 결론 먼저, 근거는 아래 펼쳐서 확인

구조 분석완료 (v1 추정 → v2 확정)
대상레거시 ERP "JAEHO" (태성S&C, 2019~2022 운영)
범위5개 대분류 · 11개 중분류 · 70개+ 화면
✅ 결론 — 신규 설계에 반영할 것 실사례 기반
  • 무역관리(USANCE, 외상수입신용장) 도메인이 실제로 존재 — 해외 원자재 수입 기반 제조업 구조임이 확정됨. 신규 SaaS에도 무역금융 연동을 반드시 검토해야 함.
  • 원자재 BOM → 구매발주 → 작업지시 → 생산실적으로 이어지는 연계가 원가 계산의 핵심 흐름 — 신규 설계 시 BOM 엔진을 별도 마이크로서비스로 분리해 자재·생산·원가계산이 공통 참조하도록 권고.
  • 초기 DLL 기반 추정(v1.0)은 무역·BOM 도메인을 놓쳤음 — 실제 화면 확인(v2.0) 전까지는 몰랐던 핵심 업무 영역. "추정만으로 설계를 확정하면 안 된다"는 근거 사례.
관련 실사례: 실패사항 #5 · 교훈 도출 #5 · Best Practice #5

아래는 위 결론이 나오게 된 실제 분석 과정입니다. 처음엔 설치된 DLL 파일명만 보고 메뉴 구조를 추정(v1.0)했는데, 실제 화면을 캡처해 확인해보니(v2.0) 무역관리·BOM처럼 추정에 없던 영역이 드러났습니다. 검색·복사가 가능하도록 구조를 텍스트로 옮겨뒀고, 확정된 원본 이미지는 맨 아래에서 그대로 볼 수 있습니다.
